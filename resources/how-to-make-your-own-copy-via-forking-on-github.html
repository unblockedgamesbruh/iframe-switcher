How to Make Your Own Copy via Forking on GitHub

Want your own version of this project? You can create an independent copy by forking the repository on GitHub.

What is a fork?

A fork is your own copy of another GitHub repository. It gives you a separate repository under your GitHub account that you can modify without directly changing the original project.

Think of a fork as making your own copy.

The original repository remains separate, while your fork becomes the version that you control.

Before you begin

You will need a GitHub account. You should also have access to the repository you want to copy.

If the repository is public, you can normally fork it directly from its GitHub page.

Fork the project

Open the GitHub repository

Navigate to the GitHub repository that contains the Resource Switcher project.

Select Fork

On the repository page, find the Fork option and select it.

GitHub will ask where you want the fork to be created.

Choose your account

Select your GitHub account as the destination for the fork.

GitHub will then create a repository under your account.

Wait for the fork to finish

GitHub will copy the repository into your account. When the process finishes, you will have your own repository.

Open your new repository

Your fork should now appear in your GitHub repositories.

The files should include the project's main HTML file, manifest, documentation, and other project files.

Your new project structure

After forking, your repository may look something like this: 

/
├── index.html
├── manifest.json
├── readme.md
├── how-to-use.md
├── resources/
│   └── how-to-make-your-own-copy-via-forking-on-github.html
└── icons/
    ├── icon-192.png
    └── icon-512.png

Make your changes

Once the repository belongs to you, you can customize the project however you like.

Change the resources

Edit index.html and add, remove, or replace resources in the resource menu.

Change the application name

Edit manifest.json to change the application name and short name.

Change the appearance

The CSS in index.html controls the menu, colors, spacing, animations, and overall appearance.

Replace the icons

You can replace the PNG files in the icons/ directory with your own application artwork, keeping the filenames and dimensions expected by the manifest.

Downloading your fork

If you want a local copy on your computer, GitHub provides options for downloading or cloning your repository.

For a simple download, use GitHub's Code menu and choose the option to download the repository as a ZIP file.

If you plan to make frequent changes, Git is another option because it lets you synchronize your local project with your GitHub repository.

Publishing your own version

A forked repository can be published using a web-hosting service that supports static HTML files.

When hosting the project, make sure the application's files remain in the expected locations. In particular, the manifest and icon paths need to match the references in index.html and manifest.json.

Important considerations

Forking creates your own repository, but it does not automatically give you ownership of the original project's content.

Check the original repository's license and any applicable notices before redistributing or publishing your modified version.

If you substantially modify the project, consider documenting what you changed so that users of your version can understand how it differs from the original.

Keeping your fork updated

The original repository may continue to receive updates after you create your fork.

GitHub provides mechanisms for synchronizing a fork with its upstream repository. The exact workflow depends on how you work with Git and whether you have made changes to your own fork.

Tip:

If you heavily customize your fork, keep track of your changes so you can decide which future updates from the original project you want to incorporate.

You're ready

Once your fork is created, the project is yours to customize within the terms of its applicable license.

You can change the resource list, visual design, application name, icons, documentation, and other parts of the project to suit your needs.
